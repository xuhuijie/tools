# caculate

工具合集 H5 页面集合，直接用浏览器打开即可使用。

**不依赖构建，每个页面都是自带全部样式与脚本的单文件。** 页面用到的第三方库
（放在 `docs/lib/`，随仓库提交）在打包时被内联进 HTML，运行时没有任何相对子资源请求——
这样手机浏览器（如 Edge / 微信）从「下载 / 文件管理器」打开本地 HTML 时也能完整渲染，
不会出现「静态样式丢失、脚本不跑」的裸页。首页把全部工具按分类铺开，顶部可搜索，
输入关键词直接命中单项工具。

## 流量点校准

按零点与误差百分比换算各流量点的校正数值：

```
校正数值 = 原始数值 + (原始数值 − 零点) ÷ 100 × 误差百分比
```

- 零点数值全局生效，一般取多次静水测量的平均值
- 每个流量点填「原始数值」与「误差百分比」，误差带符号：偏大填正、偏小填负
- 支持增删流量点、一键套用误差、清空误差、重置
- 结果区给出各点校正数值、修正量与代入过程，便于复核

## 黄金价格换算

在美元/盎司与人民币/克之间双向换算，并可按波段区间算斐波那契回调价位：

```
人民币/克 = 美元/盎司 × 汇率 ÷ 31.1034768
美元/盎司 = 人民币/克 × 31.1034768 ÷ 汇率
```

- 1 金衡盎司按 31.1034768 克计算（央行与上海黄金交易所采用值）
- **双向输入**：美元/盎司与人民币/克两个框都能填，改哪一侧，另一侧即时换算出来
- 汇率固定为换算系数，单独一个输入框，并支持自动获取
- 结果区同时给出人民币/克与人民币/千克，附换算过程与反向核对，便于复核
- 结果已展示时修改任一参数会即时刷新，无需重复点击

### 双向输入

两个价格框互为输入，不用先想清楚「该填哪个框」：

- 改美元/盎司 → 人民币/克 实时按当前汇率算出；反过来同理
- 两个框都自洽：以最后编辑的一侧为真值，另一侧由公式推出，不会出现两框互相矛盾
- 改汇率时保持最后编辑的那一侧不变，只让另一侧跟着变，避免输入被冲掉
- 正在编辑的框不会被覆盖，不会出现「打一个字被换掉」的循环同步问题
- 编辑中的框若为空或非正数会即时标红提示，但不会清空对面，方便连续重填
- 页面打开时两个框已按默认值与自动取到的汇率对齐

### 汇率自动获取

汇率不必手查，页面会自动从公开接口取当前值，并在汇率下方显示取到的数值、更新时间与来源：

| 顺序 | 接口 | 说明 |
| --- | --- | --- |
| 1 | `open.er-api.com/v6/latest/USD` | exchangerate-api.com 免费版，免密钥 |
| 2 | `api.frankfurter.dev/v1/latest` | frankfurter.dev，欧洲央行数据源，免密钥 |

- 接口按上表顺序尝试，前一个失败自动降级到下一个；全部失败则保留默认值并提示手动填写
- 请求带 10 秒超时，接口卡住不会拖住页面；离线时直接提示手动填写
- 取到的是市场中间价，仅作换算参考；银行买卖价/金店售价会有价差，实际成交以机构报价为准
- 汇率框仍可手动填写，手动改动后自动获取的提示会复位

> 这是本仓库唯一涉及网络的功能：获取失败时页面其余部分完全可用，不影响离线打开与手算。

### 斐波那契回调价位

同一页面下半部分按波段区间算回调位：

```
回调位 = 波段高点 − (波段高点 − 波段低点) × 回调比例
```

- 固定给出 0% / 23.6% / 38.2% / 50% / 61.8% / 78.6% / 100% 七个回调位，并高亮黄金分割 61.8%
- **方向**：默认按上升波段回撤，回调比例越大价位越低，0% 即波段高点、100% 即波段低点；
  填成高点低于低点会提示所填区间为回撤方向，避免方向反了还算出结果
- **价位单位跟随汇率**：默认沿用上方「美元兑人民币汇率」，把美元区间折成元/克。
  折算方式与上方换算完全一致，**按汇率折算后还要除以 1 金衡盎司的克数（31.1034768）**，
  不能只乘汇率；单位框留空即跟随，也可手填（填 1 即按美元/盎司显示），或点「套用当前汇率」一键填入
- 结果区给出各回调位价位与代入过程，人民币显示时同时附美元/盎司原值，便于复核

示例：波段 2650 → 2000 美元/盎司，汇率 7.25：

```
524.06 元/克 = [2650 − (2650 − 2000) × 61.8%] × 7.25 ÷ 31.1034768
```

## 瞬时流量与流速换算

在瞬时流量 m³/h 与流速 m/s 之间双向换算，按口径与缩进百分比折算流通截面积：

```
流速 = 流量 ÷ 3600 ÷ (π × 等效内径² ÷ 4)
等效内径 = 口径 DN × (1 − 缩进百分比 ÷ 100)
每秒脉冲数 = 流量 × 1000 ÷ 3600 ÷ 脉冲当量(ml)
```

- 口径按管段内径（mm）填入；缩进百分比是内径被削掉的比例，0 表示不缩进，输入 0～100（不含 100）
- **双向输入**：流量与流速两个框都能填，改哪一侧，另一侧即时换算出来。
  改口径、缩进百分比或脉冲当量时按最后编辑的那一侧重算，不会把输入冲掉
- **脉冲当量**按 ml 填入（每个脉冲代表的体积），结果区据此给出每秒脉冲数（脉冲/s）；
  留空则不折算脉冲频率，只做流量与流速换算
- 结果区给出流速、瞬时流量、口径、有效内径与脉冲当量、每秒脉冲数，
  并附截面积、换算过程（含脉冲频率）与反向核对，便于复核
- 结果已展示时修改任一参数会即时刷新，无需重复点击

## 校验和计算

输入一段字节，一次算出 CRC、累加和、异或校验，省得在几个网页之间来回切：

- **两种输入方式**：十六进制 HEX 与字符串 UTF-8。
  HEX 忽略空格、逗号、分号、冒号与换行，支持 `0x` 前缀，例如 `01 03 00 00 00 0A`；
  文本模式按 UTF-8 取字节，中文一个字通常 3 字节，需与设备侧编码一致
- 三项可勾选：CRC 校验、累加和、异或校验，算哪项勾哪项
- 每组结果都给出十六进制、十进制与**校验字节**，并带一键复制

### 累加和校验

```
累加和 = (各字节无符号求和) & (2^宽度 − 1)
```

- 宽度可选 8 / 16 / 32 位，取低位的方式与设备一致
- 8 位即常见的一字节累加校验（求和后取低 8 位）
- 结果按所选大端 / 小端给出校验字节顺序

### 异或校验

```
异或校验 = 各字节逐位异或，再按宽度取低 N 位
```

- 宽度可选 8 / 16 / 32 位，同样支持大端 / 小端输出
- 8 位单字节 XOR 是最常见用法，多用于简单帧校验

### 核验

- CRC 覆盖全部 60 个预设，与 `crcmod` 参考实现、`zlib.crc32` 及官方「123456789」标准校验值逐一对齐
- 累加和、异或校验与逐字节手算核对，含空输入、多字节、大端 / 小端输出等用例

### 示例

Modbus 读保持寄存器帧 `01 03 00 00 00 0A`：

```
CRC-16/MODBUS = 0xCDC5      校验字节 C5 CD（低字节先发）
累加和 8 位    = 0x0E
异或 8 位      = 0x08
```
## 首页与工具清单

`docs/index.html` 是唯一入口：全部工具分站长 / 开发 / 学习 / 生活 / 小工具五类铺在首页。
页面自上而下是**头部（站名 + 深浅色切换）→ 统计与搜索 → 分类胶囊条 → 专项工具 → 五个分类**，
桌面按容器宽度自适应多列铺满，手机单列，点任意条目直接进本地实现页。
整站没有外链，标签页里也不出现外部站点名。

首页的几个可见约定：

- **深浅色**：跟随系统（`prefers-color-scheme`），点头部按钮可手动切换并记进 `localStorage`；

  桌面端右缘另有一个箭头作可点的暗示，手机不给它留位置

要点：

- **首页可搜索可跳转**：搜索按名称、副标题与 `data-kw` 别名三者匹配，命中即只留命中的条目，
  分类导航与空分类一并收起；分类胶囊锚点直达对应分组
- **每条入口直达自己的工具**：一张页面装了多个工具（`number.html` 有 9 个），
  首页条目写成 `./page.html#tab`，页面由 `app.js` 的 `T.firstTab` 认领 hash 并切到对应页签。
  条目到页签的映射在 `tools/gen_index_page.py` 的 `ENTRY_TABS`，
  跑脚本时会逐条核对「该页面确实有这个页签」，写错直接报错；没有页签按钮的页面
  （`checksum.html` 靠勾选框切工具）用同文件里的 `HASH_TABS` 声明可用 hash
- **与已有页面的分工**：CRC / 累加和 / 异或这三类清单项指向本仓库已有的 `checksum.html`，
  它按通信协议给预设、宽度与大小端、校验字节，比 `hash.html` 更贴实际组帧；
  `hash.html` 则偏向文件与文本摘要（MD5、SHA、HMAC、Adler-32）
- **原本「不本地复刻」的条目已全部实现**：图片压缩、二维码生成识别、SSL 证书解析、条形码、
  短链、敏感词检测、网页源码查看、Markdown/HTML 编辑器、经纬度拾取这些，
  靠随仓库携带的 `docs/lib/` 第三方库 + 浏览器原生 API（canvas、FileReader、Geolocation）实现了。
  少数确实做不到纯前端的（在线端口扫描、证书链验证、工信部备案实查）改为「给清单与命令 + 说明为什么不做」，
  不假装能做
- **计时类不受后台节流影响**：`clock.html` 的秒表与计时器以 `performance.now()` 差值推算，
  不靠 tick 累加；页面切到后台被浏览器降频后回来，显示的仍是准确耗时
- **个税口径写明按估算**：工资走累计预扣预缴，本页用按月等效税率表估算并标注；
  年终奖单独计税的「多发 1 元到手反降」跳档区间会主动提醒
- 首页由 `tools/gen_index_page.py` 生成，条目数据在 `tools/catalog.json`，
  条目到实现页的映射在 `tools/local_pages.json`，条目到页签的映射在同脚本的 `ENTRY_TABS`；
  调整分类、映射或页签名后重跑脚本即可
- **一个功能一条入口**：清单里同功能的多个条目（`整除计算器` 与 `整除数计算器`、
  `大写转换器` 与 `URL编码`、三套敏感词词库等）在首页各留一条，指向各自页签，
  不再出现「点进去长得一样」

### 校验

`tools/check_algos.mjs` 把各工具页的核心算法摘出来与标准测试向量逐条比对，
改完算法跑一遍：

```bash
node tools/check_algos.mjs
# 815 通过, 0 失败
```

覆盖的向量：

- MD5、SHA-1/256/512 对 RFC 测试向量（`abc`、空串、长输入、中文）
- CRC 对 CRC RevEng 目录（`123456789` 在 8 种模型下的标准值）
- Base32/Base58/Base62 对 RFC 4648 与比特币地址样例；Punycode 对 RFC 3492（`中国` → `fiqs8s`、`münchen`）
- 金额大写覆盖零、整、角、分、负数与跨节补零等边界
- 整除判断的商/余数/「能整除吗」与整除数清单（质数只有 1 与自身、1 的清单只有 1）
- 首页页签路由：无 hash 用默认、hash 命中切过去、hash 不是本页页签时回落默认
- HMAC-SHA1/256/512 与 Node `crypto` 对照
- 日期对 ISO 8601 周号边界（如 2021-01-01 属 2020 年第 53 周）
- 子网掩码连续性、MAC 单播/组播位、WCAG 黑白对比度 21:1
- 时区换算与 Node `Intl` 对照：东京 +9、伦敦夏令时 +1、纽约夏令时 −4、印度 +5:30、UTC 0
- 几何公式对照解析解：3-4-5 直角三角形的对角线/母线、圆柱圆锥的表面积体积、串联分压与并联分流
- SQL 关键字大小写与换行、字符串字面量（含关键字与空格）不被误伤；JSON 的注释与尾逗号宽容解析
- 文本对比覆盖替换/新增/删除/忽略空格/忽略大小写/忽略空行/字符级，以及同类操作合并
- 个税分档边界（3000、12000、25000 整点不跳档）、年终奖 36000 → 36001 的跳档反转、
  并入综合所得的边际税额、BMI 四档分界、Mifflin-St Jeor 男女 BMR 定值

## 文件 / 文本 MD5 校验

`docs/md5.html` 单独一页专门算摘要，文本和文件都能算：

- **三种输入**：文本（UTF-8）、十六进制 HEX、文件上传
- **文件支持多选与拖拽**，逐个给出摘要；文件不离开本机，全程在浏览器里算
- **流式分块计算**：文件按 4 MB 分块读取，MD5 逐块累加，大文件不会一次性读进内存
- **单文件上限 50 MB**：超过上限的文件直接拦下、不参与计算，列表里标成「超出大小上限，未计算」，
  其余文件照常算，不会因为一个超限文件让整批失败
- 算法多选：MD5 / SHA-1 / SHA-256 / SHA-512，勾几个出几个

MD5 是页内实现（浏览器原生 `crypto.subtle` 不支持 MD5），
SHA 系列走原生 `crypto.subtle`，因此 SHA 需要 https 或 localhost 环境；
本地用 `file://` 直接打开时 SHA 会提示「当前环境不支持」，MD5 不受影响。

### 为什么文件要分块

一次 `file.arrayBuffer()` 读 50 MB，在中低端手机上很容易触发内存抖动甚至崩页。
分块读入后逐块喂给 MD5 状态机，页面的内存占用与文件大小无关，只与块大小有关。

### 核验

- MD5 与 `md5sum` / `hashlib` / `node:crypto` 在空文件、`abc`、中文、5 MB 随机数据上逐一对齐
- 随机切分成不同大小的块与整块一次算，结果一致（验证状态机可续算）
- SHA-1 / SHA-256 / SHA-512 与系统 `sha1sum` / `sha256sum` / `sha512sum` 一致

## 使用

直接用浏览器打开 `docs/index.html`：全部工具按分类铺在首页，顶部搜索直达单项，点击即进对应计算页。
也可以直接打开任意页面，或通过静态托管发布（如仓库 Pages / 云原生构建）。

不需要构建、不需要装依赖、不需要起服务。**派发出去的 `docs/*.html` 都是自包含的单文件**：
页面共用的样式与工具函数（`docs/app.css`、`docs/app.js`）、各页自己的脚本、以及第三方库
（`docs/lib/`，见该目录 README）在打包时已全部内联，打开时不再请求任何相对资源，断网可用。

可编辑的源在 `docs/_src/*.html`：里面仍写 `<link href="./app.css">`、`<script src="./app.js">`
这类引用，改完跑一次 `python3 tools/inline_pages.py`，把资源内联后输出到 `docs/*.html`。
之所以这一层内联不能省：手机版 Edge 从 `content://`（下载 / 文件管理器）打开页面时，
浏览器会渲染主文档却拦掉相对子资源，页面的样式与脚本全丢，只剩一坨裸文字。
把资源内联进 HTML 后就没有可拦的子资源，问题不再出现。

### 整站单文件 `docs/all.html`

内联只解决了 css/js 这类子资源；从 `content://` 打开时，页面里 `./page.html` 这种
「跳到另一个文件」的链接同样会被拦，报「文件找不到」——单独打开某个 html 正常，
从首页点链接进去就进不去，就是这么来的。

`python3 tools/bundle_site.py` 把全部 30 个页面合成一份自包含的 `docs/all.html`：
每页一个 `<section class="page" data-name="xxx.html">`，页内脚本收在 section 里、
首次切到时才执行；`app.js` 见到这种结构就接管导航，点链接改成文档内切 section，
不走任何文件跳转，离线也整站可用。分发时给这一个文件就够。

各页原本共用同一套 id（`tabs` / `input` / `output`…），合到一份文档里会互相抢，
所以 `T.$` 只在当前活动页里找；页内自带的 `$` 定义在打包时改写成走 `T.$`，
`markTab` / `firstTab` 也只看当前页。

一个页面里的脚本**要把 section 里那几条 `script[type="text/x-page-init"]` 逐条跑完**，
不能只跑第一条：随页面内联进来的第三方库（DOMPurify、marked、bwip-js 等）在本页脚本
之前各占一条，只跑第一条的话本页脚本永远轮不到——`web.html`（网页源码）、
`crypto2.html`（证书与密钥）、`codec.html`（二维码）就是这样点按钮没反应、页签也切不动的。

地址栏只记「在哪一页」（`#page=web.html`），页签状态不写地址：`#<页签名>` 这个通道被各页
自己的页签逻辑占着（如 `checksum.html` 会把它改写成 `#crc`），争它只会互相踩。
单文件里 `syncHash` 是 no-op，`firstTab` 也要求「本页真有这个页签」才认——
否则上一页留下的 `#ssl` 会把这一页顶到默认页签。

散装单页不受影响：`app.js` 里没有 `section.page` 时一切照旧，`docs/*.html` 仍可单独打开。

### 更新与部署

页面内**不带自动更新**：分发出去的每一份都是当次打包产物，不自查版本、不联外网。

- 改完页面：`python3 tools/gen_index_page.py` → `python3 tools/bundle_site.py` 重跑产物
- 部署：把 `docs/` 目录重新上传到站点（如 Cloudflare），由维护者手动完成
- 拿到旧版的读者：重新下载 / 重新访问站点即可，页面自己不会去拉新版本
